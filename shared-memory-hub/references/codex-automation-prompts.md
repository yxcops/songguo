# Codex 自动化提示词模板

这些提示词只是模板。使用前要替换设备名、路径和时间安排。

## Codex 每日记忆整理

```text
整理刚过去一天的 Codex 本机会话记录，并按共享记忆库规则输出到 AI智能体记忆库。

只处理 Codex 自己的会话，不整理 Hermes、Claude Code 或其他智能体。

先读取共享记忆库里的 01-核心规则，再读取 Codex 本机会话记录。

只整理有长期价值的内容，不写流水账。

如果用户明确说“这个记一下”“这个有价值”“这个沉淀一下”“以后按这个来”“后续任务清单要记得核对”等表达，必须纳入每日摘要或 03-候选确认清单，不能因为 AI 自己判断价值不足而跳过。

生成聊天摘要到 AI智能体记忆库/04-聊天摘要。

若发现有沉淀价值但尚未确认的经验或规则建议，写入 AI智能体记忆库/03-候选确认清单。

不能直接修改 AI智能体记忆库/02-可复用经验库 或 AI智能体记忆库/01-核心规则。

新文件必须包含 source_platform、source_device、source_type、created_at、status、applies_to。

source_platform 表示内容原始来源，不表示本轮整理者。只整理 Codex 自己会话时写 Codex；如果合并或整理来自其他平台的既有候选，不要改写其原始来源。

如果本轮发现共享记忆库规则需要补充，优先更新 shared-memory-hub Skill；若只能先改本地规则或自动化提示词，必须记录为待同步项，避免本地规则和 Skill 分叉。

不要写入密码、Token、Cookie、API Key、账号恢复码或未脱敏的敏感配置。

任务结束时简短说明检查了哪些会话、写入了哪些文件、哪些内容因价值不足被跳过、哪些内容是因为用户明确要求而记录。
```

## 每周候选确认审阅

```text
只读检查 AI智能体记忆库/03-候选确认清单，生成一份待用户确认的整理建议。

先读取共享记忆库里的 01-核心规则，再检查 03-候选确认清单。

不要修改、移动、删除、创建任何共享记忆库文件。

不要直接修改 02-可复用经验库 和 01-核心规则。

对每条候选记忆按四类归类：
- 建议升级到 02-可复用经验库
- 建议继续留在 03-候选确认清单
- 建议归档到 90-归档废弃
- 建议作为 01-核心规则候选提交用户确认

每条建议都要写清楚依据：它解决了什么问题、是否有可复用步骤或规则、是否已经被验证、是否和现有内容重复、是否可能过期。

建议升级到 02-可复用经验库时，必须同时检查并列出建议保留的 source_platform 和 source_device。来源字段优先继承原候选：Hermes 产生的候选升级后仍写 Hermes，Codex 产生的候选升级后仍写 Codex。整理者或审阅者可以写在正文说明里，不要覆盖 source_platform。

如果原候选的属性字段、文件名、标题或正文对来源给出冲突信息，把该条列为“来源待确认”，不要建议直接升级。

如果候选审阅过程中发现规则或模板缺口，先列为需要用户确认的 Skill 同步项，不要只改本地规则。

最后明确列出需要用户确认的选项，等待用户明确同意后再执行任何文件变更。
```
