# 平台接入说明

这个 Skill 的核心是读书模式、笔记格式、阅读画像和推荐书单规则。以下能力不能只靠 Skill 自动生效，需要平台额外接入。

## 安装后第一次使用

用户安装后，先说明三件事：

1. 核心功能可以直接用：读书模式、讨论、整理读书笔记、准备阅读画像和推荐书单草稿。
2. 写入 Obsidian 或本地目录需要用户先确认保存位置。
3. 阅读画像可以基于当前平台记忆或项目资料初始化，但必须由用户明确授权读取范围。
4. 自动定时、渠道推送、读取日记、历史对话或共享记忆，需要所在平台本身支持，并且需要用户明确授权读取范围。

推荐回复：

```text
每日读书 Skill 已可使用。你可以直接说“开始读书”，也可以说“开始读《书名》”进入读书模式。

如果你希望我把笔记写进 Obsidian 或本地目录，请告诉我想放在哪个文件夹下面，或者告诉我你已经有的读书笔记目录。
如果你愿意，我也可以读取你授权的项目说明、共享记忆摘要或历史摘要，先生成阅读画像资料包，再归纳成阅读画像，用于后续推荐。
如果你希望每周一早上自动推荐并发送书单，需要再配置你当前平台的定时任务和发送渠道。
```

## 首次设置流程

如果还没有每日读书目录，先问用户目录位置，不要猜测路径，也不要立即创建文件。

用户给出目录后，先展示将创建或复用的结构，等用户确认后再创建。推荐用脚本的 `plan` 命令预览，用 `init` 命令创建。

```bash
python3 scripts/reading_tool.py --parent /path/to/folder plan
python3 scripts/reading_tool.py --parent /path/to/folder init
```

支持三种目录方式：

| 用户意图 | 脚本参数 | 处理方式 |
|---|---|---|
| 放到某个目录下面 | `--parent /path/to/folder` | 创建或复用 `/path/to/folder/每日读书` |
| 这个目录就是每日读书目录 | `--root /path/to/每日读书` | 直接复用这个目录 |
| 已经有读书笔记目录 | `--notes-dir /path/to/读书笔记` | 把它作为书籍笔记目录，不再嵌套新的 `读书笔记` |

如果用户给的目录里已经有 `读书笔记` 加 `每周推荐书单` 或 `每周推荐清单`，把它判断为已有每日读书根目录，直接复用。

## 通用目录

建议使用这个结构：

```text
每日读书/
├── 读书笔记/
├── 每周推荐书单/
├── 阅读画像.md
└── 设置.md
```

如果用户使用 Obsidian，可以放在：

```text
每日读书/
```

这只是推荐位置，不要硬编码。

如果用户已经有 `每周推荐清单` 这个文件夹，不要强行改名成 `每周推荐书单`；直接复用已有名称。

## 阅读画像初始化

阅读画像初始化的目标不是保存用户历史，而是从授权资料里提炼“选书依据”。

推荐流程：

1. 先确认每日读书目录已经初始化。
2. 说明可读取的来源，并让用户确认具体范围。
3. 只读取明确文件或明确项目目录，不读取整个私人目录。
4. 用 `profile-context` 生成资料包。
5. 读取资料包，把稳定结论写入 `阅读画像.md`。
6. 在 `设置.md` 记录已读取来源、未读取来源和初始化状态。

示例命令：

```bash
python3 scripts/reading_tool.py --root /path/to/每日读书 profile-context \
  --project-dir /path/to/已授权项目 \
  --source /path/to/已授权记忆摘要.md \
  --save
```

`--project-dir` 只读取常见项目说明文件、`Docs/*.md` 和 `docs/*.md`；不会扫描项目里的所有文件。`--source` 只接受明确文件路径，不接受整个私人目录。

`profile-context` 只生成资料包，不等于已经完成阅读画像初始化。更新 `阅读画像.md` 时，必须形成这些结论：

- 稳定画像。
- 阶段画像。
- 临时信号。
- 用户现在在做什么。
- 近期反复关注的问题。
- 正在补的能力。
- 更适合的书籍类型。
- 暂时不适合继续堆的书。
- 下一阶段推荐策略。
- 画像变更记录。
- 已读取来源、未读取来源和可信度。

不要把原始聊天、日记全文、账号、Token、Cookie、代理配置、密钥、未脱敏路径写进阅读画像。

## Codex

Codex 适合做：

- 手动进入读书模式。
- 读取本地目录并整理 Markdown 笔记。
- 根据用户给出的素材生成每周推荐书单草稿，并继续填入 5 本具体推荐书。
- 读取当前项目的 `AGENTS.md`、`README.md` 和 `Docs/*.md`，用于初始化阅读画像。
- 读取用户明确指定的本地记忆摘要文件。

Codex 是否能自动定时运行，取决于当前客户端是否开放自动化工具。没有自动化工具时，不要承诺会自动推送。

如果 Codex 支持自动化，推荐任务语义：

```text
每周一 06:00，使用 daily-reading Skill：
1. 运行 scripts/reading_tool.py context --profile-max-chars 0，完整读取阅读画像，并读取近期读书笔记和历史推荐书单。
2. 只读取用户明确授权的额外记忆文件；未授权时不要读取日记、聊天历史或私人目录。
3. 检查上下文包是否有“已截断”；如果阅读画像被截断，先重新生成上下文包。
4. 基于上下文填充 5 本书的每周推荐书单草稿。
5. 当前平台能联网或能查资料时，推荐前必须核对作者、原书名、译者或版本、出版社、出版日期和可获得性，并写入核验来源。
6. 每本书必须写质量依据和质量风险；可参考豆瓣、Goodreads、出版社页、图书馆目录、课程书单、可靠书评、引用情况或长期读者口碑，但评分不能作为唯一理由。
7. 写入“每日读书/每周推荐书单/2026年6月22日~6月28日 每周推荐书单.md”这类自然周日期范围文件。
8. 如果用户配置了发送渠道，只发送书单摘要和文件位置。
```

## Claude Code

Claude Code 适合做：

- 在项目或本地目录里维护读书笔记。
- 根据用户给出的文件和上下文整理推荐书单。
- 读取当前项目说明文件，并把用户授权的历史摘要转成阅读画像线索。

如果没有长期会话状态或定时能力，就把“一小时自动退出”和“每周自动推荐”作为使用提醒，而不是承诺已生效。

不要默认把 `history.jsonl` 当成完整会话，也不要默认读取原始 session 全文。更稳的做法是让用户授权明确的历史摘要文件，或先由平台把有价值会话整理成摘要，再交给 `profile-context`。

## Hermes

Hermes 可以做：

- 通过 Skill 进入读书模式。
- 写入 Obsidian 或本地 Markdown。
- 通过 cron 每周触发推荐书单。
- 如果配置了渠道，可以把推荐书单发到指定渠道。
- 读取用户授权的共享记忆摘要、Hermes 长期记忆摘要或项目摘要，用于初始化阅读画像。

Hermes 安装后不要默认创建定时任务。需要用户明确同意后再配置。

推荐的 Hermes 定时任务语义：

```text
每周一 06:00，使用 daily-reading Skill：
1. 运行 scripts/reading_tool.py context --days 45 --profile-max-chars 0，完整读取阅读画像，并读取近期读书笔记、近期推荐书单。
2. 只读取用户允许的额外记忆文件，例如共享记忆摘要、近期项目摘要或日记摘要。
3. 检查上下文包是否有“已截断”；如果阅读画像被截断，先重新生成上下文包。
4. 填充本周 5 本推荐书单草稿，并在“本周判断依据”里列出读取范围、核验来源、质量依据和质量风险。
5. 当前平台能联网或能查资料时，推荐前必须核对作者、原书名、译者或版本、出版社、出版日期和可获得性。
6. 写入“每日读书/每周推荐书单/2026年6月22日~6月28日 每周推荐书单.md”这类自然周日期范围文件。
7. 如果用户配置了渠道，再发送书单摘要和文件位置。
```

一小时自动退出读书模式可以用 `scripts/reading_tool.py expire --minutes 60` 做状态检查。是否定时执行由 Hermes 配置决定。

## 每周自动发送书单的配置清单

配置自动发送前，必须确认以下信息：

| 项目 | 必须确认的内容 |
|---|---|
| 保存位置 | 每日读书根目录或现有读书笔记目录 |
| 运行时间 | 默认每周一 06:00，用户可改 |
| 读取范围 | 阅读画像、读书笔记、历史书单；额外记忆必须逐项授权 |
| 推荐数量 | 固定 5 本 |
| 输出文件 | `每周推荐书单/2026年6月22日~6月28日 每周推荐书单.md` 这类自然周日期范围文件 |
| 发送渠道 | 例如飞书、Telegram、邮件、微信助手；未配置则只写文件 |
| 发送内容 | 建议只发送 5 本书标题、推荐理由摘要和文件位置 |

不要默认把完整日记、聊天记录、私人记忆原文发送到外部渠道。需要发送时，只发送书单结果，不发送原始上下文。

## 基于记忆的推荐范围

默认允许读取：

- `阅读画像.md`
- `读书笔记/` 下近期 Markdown 笔记
- `每周推荐书单/` 或 `每周推荐清单/` 下近期书单

需要用户逐项授权后才可读取：

- 日记摘要
- 长期记忆摘要
- Codex 或 Hermes 历史摘要
- Claude Code 历史摘要
- 项目资料
- 微信读书书架、笔记或划线

推荐用脚本生成上下文包：

```bash
python3 scripts/reading_tool.py --root /path/to/每日读书 context --days 45 --profile-max-chars 0
```

如果用户授权额外记忆文件：

```bash
python3 scripts/reading_tool.py --root /path/to/每日读书 context \
  --extra-source /path/to/已授权的长期记忆摘要.md
```

`--extra-source` 只接受明确文件路径。不要传入整个私人目录。

阅读画像初始化时，优先把这些额外资料整理进 `阅读画像.md`，之后每周推荐默认读取阅读画像，不要每周重复读取完整历史。

## OpenClaw

OpenClaw 可以使用同一套 Skill 规则。是否能自动定时、发送消息、读取历史，取决于 OpenClaw 的具体部署和权限。

接入时先检查：

- 是否能读写用户指定目录。
- 是否有定时任务能力。
- 是否有消息渠道。
- 是否被允许读取日记、历史摘要或其他个人上下文。

## 权限边界

不要默认读取这些内容：

- 日记
- 私聊记录
- Codex 历史
- Claude Code 历史
- 微信读书书架
- NAS 文件

只有用户明确授权，且当前平台确实能访问时，才使用这些资料。
