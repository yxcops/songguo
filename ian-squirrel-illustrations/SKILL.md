# Ian 小松鼠正文配图

## 核心定位

为中文内容设计和生成带固定小松鼠 IP 的正文配图。目标不是做普通可爱头像或儿童插画，而是让小松鼠成为信息整理员、知识收纳员、工作流搬运者，把文章里的关键判断、流程、结构、状态或隐喻变成清楚、有记忆点的画面。

默认视觉 IP 是“小松鼠”：橙棕色毛绒身体、奶油色脸颊、大圆眼、两颗门牙、圆耳朵、短爪子、深绿色卷曲大尾巴，尾巴上有蓝色发光线路和圆形节点。

## 先读这些参考

按任务需要读取，不要一次塞满上下文：

- `references/style-dna.md`：整体画风、颜色、禁忌。
- `references/squirrel-ip.md`：小松鼠 IP 的外形、性格、动作库和禁忌。
- `references/state-and-scale.md`：小松鼠状态库、画面占比、封面/正文图差异。
- `references/composition-patterns.md`：结构类型和原创隐喻方法。
- `references/prompt-template.md`：单张生图提示词模板。
- `references/qa-checklist.md`：生成后检查和迭代规则。
- `assets/character-reference/squirrel-main.png`：固定角色参考图。生图工具支持参考图时，优先作为 reference 传入。

## 工作流

### 1. 消化正文

先读用户给的正文、链接、Markdown、截图或主题，提炼：

- 核心观点是什么。
- 哪些段落适合用图解释。
- 哪些地方只需要文字，不需要图。
- 小松鼠应该参与哪个核心动作。
- 这张图是封面主视觉还是正文解释图。
- 小松鼠应该占画面的多少，是否需要缩小让结构更清楚。

不要平均配图。优先选择认知锚点，例如：混乱到收拢、候选到沉淀、输入到输出、分层整理、经验复用、信息过载、任务分拣、知识缓存。

### 2. 先出配图策略

如果用户只是说“分析怎么配图 / 给配图方案 / shot list”，先给策略，不生成图。每张图写清楚：

- 放在哪个段落后。
- 图的主题。
- 核心意思。
- 结构类型。
- 小松鼠在图里做什么。
- 建议元素。
- 建议中文标注词。
- 是否必须使用角色参考图。

默认 1-4 张；长文也不要轻易超过 6 张。够用就好，避免把正文做成画册。

正文解释图默认让结构优先：小松鼠占画面 18%-30%，一般不要超过 35%。封面或主视觉才允许小松鼠占 35%-50%。

### 3. 单张生成

如果用户明确要求“生成 / 输出 / 做图 / 帮我生成”，每张图单独生成，不要把多张图拼在一张里。

每张图只讲一个核心结构。提示词必须包含：

- 目标比例和用途。
- 视觉用途：正文解释图 / 封面主视觉 / 平台卡片。
- 小松鼠作为核心动作主体。
- 正文解释图里小松鼠不要大头居中，不要复刻参考图的 App 图标构图。
- 小松鼠默认画全身或 3/4 身，放在画面侧中或中下区域，给流程和结构留空间。
- 橙棕毛绒身体、奶油脸颊、圆耳朵、大圆眼、两颗门牙、短爪子。
- 深绿色卷曲大尾巴，尾巴上有蓝色发光线路和圆形节点。
- 不要普通棕色松鼠、不要儿童绘本、不要普通宠物头像。

如果使用 ListenHub image-gen 或其他支持参考图的工具，必须把 `assets/character-reference/squirrel-main.png` 作为参考图传入。比如 ListenHub CLI 应添加：

```bash
--reference "$HOME/.codex/skills/ian-squirrel-illustrations/assets/character-reference/squirrel-main.png"
```

如果当前工具不支持参考图，则只使用文字提示词，但要明确告诉用户：角色一致性会比参考图模式弱。

### 4. 检查与迭代

生成后检查 `references/qa-checklist.md`。如果出现以下问题，优先重生成或局部编辑：

- 不是同一只小松鼠。
- 丢掉深绿色卷曲尾巴。
- 丢掉蓝色发光线路。
- 太像普通卡通松鼠或儿童绘本。
- 小松鼠只是装饰，没有做核心动作。
- 小松鼠占比过大，抢走结构表达。
- 画成大头主视觉，而不是正文解释图。
- 画面像 PPT、课程页或复杂架构图。
- 中文太多或错字严重。

### 5. 保存交付

如果用户在 workspace 内工作，把最终图保存到：

```text
assets/<article-slug>-squirrel-illustrations/
```

按顺序命名：

```text
01-topic-name.png
02-topic-name.png
```

保留原始生成文件，不要覆盖已有资产，除非用户明确要求替换。

## 输出口径

生成前的策略输出要短而准。生成后的交付要包含：

- 生成了几张。
- 每张图的用途。
- 保存路径。
- 是否使用了参考图。
- 哪些图最稳，哪些图是可选。

不要长篇解释风格理论；让图自己说话。
